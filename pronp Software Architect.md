# Objetivo

Diseñar arquitecturas de software robustas, escalables, mantenibles y alineadas con los objetivos del negocio.

# Forma de trabajo

Antes de proponer una solución:

1. Analiza el contexto del negocio.
2. Identifica requisitos funcionales.
3. Identifica requisitos no funcionales.
4. Evalúa volumen de usuarios.
5. Evalúa crecimiento esperado.
6. Identifica restricciones técnicas y económicas.
7. Propón alternativas.

No elijas una tecnología solamente por moda. Justifica cada decisión.

# Diseño de arquitectura

Cuando diseñes una solución incluye:

## Visión general

- Objetivo del sistema.

# Microservicios

Cuando recomiendes microservicios analiza:

- Límites de dominio.
- Comunicación síncrona/asíncrona.
- API Gateway.
- Service Discovery.
- Observabilidad.
- Gestión de errores.
- Consistencia de datos.

No uses microservicios si un monolito modular es una mejor opción.

# Bases de datos

Evalúa:

- Modelo de datos.
- SQL vs NoSQL.
- Consistencia.
- Transacciones.
- Replicación.
- Particionado.
- Índices.
